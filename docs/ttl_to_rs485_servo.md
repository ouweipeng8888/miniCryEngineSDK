# TTL转RS-485与伺服电机通信指南

本指南概述了如何使用TTL转RS-485转换器与伺服电机进行半双工串行通信，适用于常见的工业伺服驱动器或采用RS-485接口的智能伺服舵机。

## 1. 基本概念

- **TTL串口**：常见于微控制器（如Arduino、STM32）或单板机（如Raspberry Pi）的UART接口，电平通常为3.3V或5V，单端通信。
- **RS-485总线**：差分信号、抗干扰能力强，支持多机节点、半双工通信，传输距离可达数百米。
- **TTL转RS-485模块**：内部包含差分驱动/接收芯片（如MAX485、SP3485等），负责在TTL与RS-485电平之间转换，并提供方向（发送/接收）控制引脚。

## 2. 硬件连接

1. **电源**：
   - 给转换模块供电（通常为5V或3.3V）。
   - 确保与控制器和伺服驱动器的地线共地。
2. **信号线**：
   - 控制器的TX连接到模块的DI（Data In），RX连接到RO（Receiver Out）。
   - 模块的A/B差分线连接到伺服驱动器的RS-485+（A）和RS-485-（B）。
3. **方向控制（DE/RE）**：
   - 大多数转换模块需要通过DE（Driver Enable）和/或RE（Receiver Enable）引脚控制半双工方向。
   - 将DE与RE（若为低有效）连在一起，通过单一GPIO控制：发送前拉高使能驱动器，发送完成后拉低切换到接收。
4. **终端电阻**：
   - 总线两端加120Ω终端匹配电阻，并考虑加偏置电阻（上拉/下拉）防止线路悬空。

## 3. 通信参数

- **波特率、校验位、停止位**：按照伺服驱动器手册设置；常见配置为115200 bps、8N1。
- **协议**：
  - 工业伺服多采用Modbus RTU或厂商自定义协议。
  - 智能舵机（如舵机总线协议）通常以固定帧格式发送。
- **超时与轮询**：设定合理的响应超时和重发机制。

## 4. 软件流程示例

1. 初始化串口并设置波特率、数据格式。
2. 配置方向控制GPIO并默认置于接收模式。
3. 准备指令帧，发送前将GPIO置发送状态，写串口数据。
4. 等待发送FIFO空，切换回接收模式，监听伺服驱动器回复。
5. 解析响应帧，根据协议处理数据。

下面给出伪代码示例（以半双工Modbus RTU为例）：

```c
void rs485_send(uint8_t *frame, size_t len) {
    gpio_set(DE_RE_PIN, HIGH);   // 切换到发送
    uart_write(frame, len);
    uart_flush();                // 等待FIFO发送完毕
    gpio_set(DE_RE_PIN, LOW);    // 切换回接收
}

int rs485_exchange(uint8_t *tx, size_t tx_len, uint8_t *rx, size_t max_rx) {
    rs485_send(tx, tx_len);
    return uart_read(rx, max_rx, TIMEOUT_MS);
}
```

## 5. 伺服驱动器注意事项

- 按照驱动器手册匹配通信接口类型（部分支持RS-232、RS-485、CAN等多种接口）。
- 若驱动器采用差分对称供电或需要使能脚（EN），需在通信前确保驱动器处于可接收状态。
- 某些伺服需要先发送握手/上电初始化命令。

## 6. 故障排查

- **无响应**：检查波特率、地址、帧格式是否匹配；确认DE/RE方向切换及时；确保总线终端电阻和供电稳定。
- **数据错误**：排查线缆干扰、屏蔽与接地；验证CRC或校验码；检查是否有多个节点冲突发送。
- **通讯间歇中断**：查看伺服驱动器是否有报警状态；尝试降低波特率或缩短线缆。

## 7. 安全与电磁兼容

- 在工业环境中使用屏蔽双绞线并正确接地。
- 若控制器与伺服驱动器电位差大，考虑加隔离型RS-485转换模块。
- 遵循伺服厂商提供的接线和安全操作指南。

通过正确的硬件连接、方向控制和协议实现，可以稳定地利用TTL转RS-485模块与伺服电机进行通信，实现状态监控和指令控制。
